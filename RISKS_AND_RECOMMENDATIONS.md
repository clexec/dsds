# Риски и рекомендации по работе бота

Этот документ содержит перечень критических узлов бота и рекомендации по их эксплуатации, чтобы избежать сбоев и потери данных.

## 1. База данных (db.json)
**Риск:** Файл `db.json` является единственным хранилищем данных. При некорректном завершении работы бота или одновременной записи из двух процессов файл может быть поврежден.
**Что сделано:**
- Внедрена **атомарная запись**: бот сначала пишет во временный файл, а затем переименовывает его.
- Добавлены **файловые блокировки (portalocker)** и **распределенные блокировки (Redlock)** через Redis.
**Рекомендация:** Всегда делайте бэкап `db.json` перед обновлением кода. Не редактируйте `db.json` вручную во время работы бота.

## 2. Redis и Кэширование
**Риск:** Бот использует Redis для лимитов и анти-спама. Если Redis упадет, бот может начать работать медленнее или сбросить текущие кулдауны.
**Что сделано:**
- Реализован **Graceful Fallback**: если Redis недоступен, бот автоматически переключается на хранение лимитов в оперативной памяти.
**Рекомендация:** Для стабильной работы в продакшене убедитесь, что Redis запущен с включенным сохранением на диск (AOF или RDB).

## 3. Система локализации (i18n)
**Риск:** Если в файлах локации (`ru.yml`, `en.yml`) будет синтаксическая ошибка (лишний пробел, неверный отступ), бот не сможет загрузить переводы и может упасть при старте.
**Что сделано:**
- Добавлен механизм **fallback**: если перевод не найден, бот вернет исходный ключ.
- Все неизвестные ключи пишутся в `missing.json`.
**Рекомендация:** При добавлении новых строк проверяйте YAML-файлы на валидность.

## 4. Смена языка и одобрение @seyats
**Риск:** Смена глобального языка бота — это серьезная операция, которая затрагивает все группы сразу.
**Что сделано:**
- Теперь смена языка владельцем требует **одобрения @seyats**.
- При первом запуске владелец выбирает язык, который становится языком по умолчанию для всех групп.
**Рекомендация:** Не меняйте язык бота без необходимости, так как это может сбить настройки в уже подключенных группах.

## 5. Лимиты Telegram API
**Риск:** При массовых рассылках или очень активном флуде в группах бот может получить 429 ошибку (Too Many Requests).
**Что сделано:**
- Добавлены кулдауны на нажатие кнопок и команды в личке.
**Рекомендация:** Не ставьте слишком агрессивные настройки анти-флуда, чтобы бот не превысил лимиты на удаление сообщений.
